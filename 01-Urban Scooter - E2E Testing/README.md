# Urban Scooter — End-to-End Testing

## What is this?

A QA testing project completed as part of the TripleTen QA Tester Bootcamp.

The project focused on validating the end-to-end user journey of a web-based scooter rental application, from account creation and scooter selection to order completion.

## Product & Functionality Under Test

Urban Scooter is a web application that allows users to rent scooters.

The testing scope included:

- User registration and authentication
- Scooter rental flow
- Form validation
- Rental parameters and business rules
- Order confirmation
- Payment-related functionality
- UI behavior
- Cross-browser compatibility

## Objective

To validate the application's core functionality against its requirements and identify defects that could affect the user experience or prevent successful order completion.

Testing priorities were based on user impact and business risk, with particular attention to the main rental flow and input validation.

## Scope

Testing included:

- Functional testing
- UI testing
- End-to-end testing
- Boundary Value Analysis (BVA)
- Equivalence Partitioning (EP)
- Cross-browser testing
- Defect reporting

## Artifacts

- **README.md** — Project overview, testing scope, objectives, and results.
- **Evidence/** — Selected screenshots supporting test results and documented defects.

## Key Decisions

Test scenarios were prioritized around the main rental journey, input validation, and functionality with direct impact on successful order completion.

Boundary Value Analysis and Equivalence Partitioning were applied to input fields where requirements defined valid ranges and conditions.

Defects were documented with reproducible steps, expected and actual results, severity, and supporting evidence.

## Results

- Designed and executed end-to-end test cases based on project requirements.
- Applied structured test design techniques to validate input boundaries and business rules.
- Identified and documented functional and UI defects.
- Validated the application across different browsers.
- Created reproducible defect reports with supporting evidence.

## What I would improve next

For a future iteration, I would expand automated coverage for the main rental flow and add broader regression coverage for critical functionality.
